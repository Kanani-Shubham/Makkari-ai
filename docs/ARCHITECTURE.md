# Makkari AI — System Architecture & Capability Runtime

## 1. Executive Summary

Makkari AI is a unified intelligence operating system combining multi-model orchestration (Google Gemini, OpenAI, Anthropic, Groq, OpenRouter, and local Ollama), a 3-tier persistent memory engine, a universal skill system, canonical tool execution, and the Model Context Protocol (MCP).

## 3. Key Architectural Pillars

### A. 3-Tier Memory System
1. **Tier 1 (Conversation Turn History)**: Active dialogue turns formatted for the provider.
2. **Tier 2 (Conversation Summaries)**: Multi-turn syntheses generated by background post-chat workers.
3. **Tier 3 (Persistent User Memories)**: Factual preferences, project contexts, and technical constraints stored with RLS in `public.user_memories`. Memory is treated strictly as **untrusted context** wrapped inside `<user_context>`.

### B. Universal Skill Engine (`skills/`)
Skills are defined in markdown files (`skill.md`) with YAML frontmatter. Instead of injecting all markdown files into every prompt, Makkari generates a lightweight `<available_skills>` manifest at runtime (<10ms). When a user query matches skill triggers, the skill resolver dynamically injects only the targeted workflow instructions.

### C. Universal Tool Engine (`lib/ai/tools/`)
Tools share a single internal representation (`ToolDefinition`) and are automatically converted to provider-specific schemas:
- Google Gemini `FunctionDeclaration`
- OpenAI / Groq `function` format
- Anthropic `name, description, input_schema` format

### D. Model Context Protocol (MCP) Platform (`lib/ai/mcp/`)
Makkari acts as an MCP client supporting Streamable HTTP / SSE transports, remote tool discovery, tool catalog caching (conforming to the 2026 MCP specification), and granular permission enforcement (read vs. write vs. delete).
